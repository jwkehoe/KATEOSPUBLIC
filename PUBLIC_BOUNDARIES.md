# KateOS Base: public boundaries

KateOS Base is a practical method and a set of local working files. It helps a
person preserve objectives, source authority, corrections, work state, and a
repeatable way of checking the work.

It is not a model, a provider feature, a promise of hidden memory, or evidence
that an assistant retains a stable identity between sessions.

## What the Base can support

- A global working core and optional project context.
- Clear authority, source, and correction rules.
- Append-only task checkpoints and resumption from recorded work.
- A way to distinguish a local file from an observed behavior.
- A small, inspectable recovery exercise.

## What the Base does not establish

- A local instruction file does not prove it was placed in a provider setting.
- A placed setting does not prove a provider applied it.
- One good response does not prove durable continuity or recovery.
- A score does not establish broad model quality, productivity, or release
  readiness without the recorded conditions and outputs behind it.
- KateOS Base does not include another person's private history, client work,
  credentials, provider memory, personal canon, or restricted sources.

## User responsibility

The user decides the objective, authority, and acceptance standard. Before
changing a real provider setting, preserve the prior setting privately, read
back the changed surface, and keep a rollback path. Keep private data out of
public templates, repositories, and examples.

Use the source and state files as evidence of a method. State only what the
available record supports.
